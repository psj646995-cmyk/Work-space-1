# 풋살 하이라이트 / 경기 분석 프로토타입

풋살/축구 경기 영상을 넣으면 두 가지 모드로 쓸 수 있다:

- **하이라이트 모드**: 골 장면 후보를 자동으로 찾아 클립으로 잘라준다
- **경기 분석 모드**: 풀경기/편집된 경기 영상에서 터치·슈팅 후보를 찾아, 팀 미팅에서 바로 볼 수 있는 HTML 리포트로 정리해준다 (참고용 득점확률 근사치 포함 가능)

경기 스탯을 넣으면 **선수 평점과 MOM(Man of the Match)을 계산**하는 기능도 있다.

"지금 당장 실현 가능한 범위"만 구현했고, 딥러닝 기반 액션 인식이나 얼굴/신체
인식, 정밀한 xG 계산처럼 폰 한 대로 찍은 영상에서 현재 기술로 안정적으로
자동화하기 어려운 기능은 의도적으로 포함하지 않았다 (아래 [한계와 다음
단계](#한계와-다음-단계) 참고).

## 사전 준비 (한 번만 하면 됨)

1. **Python 3.10 이상** 설치. Windows는 [python.org/downloads](https://python.org/downloads)에서
   설치 파일을 받아 설치하되, 설치 화면에서 **"Add python.exe to PATH"**를 꼭 체크하세요.
2. **ffmpeg** 설치 (영상 자르기/썸네일 추출에 필요, pip으로는 설치 안 됨)
   - **Windows에서 `실행하기.bat`/`start.bat`으로 실행할 거라면 이 단계도 안 해도 된다** — 없으면 첫 실행 때 `bin/` 폴더에 자동으로 받아둔다 (몇 분 정도 걸릴 수 있음). 회사/학교 네트워크라 자동 다운로드가 막혀 있으면 아래 링크에서 직접 받아 PATH에 추가하면 된다
   - Windows(수동): [ffmpeg.org](https://ffmpeg.org/download.html)에서 받아 PATH에 추가
   - Mac: `brew install ffmpeg`
   - Linux: `apt-get install -y ffmpeg`
3. **파이썬 의존성 설치**
   - **Windows에서 `실행하기.bat`/`start.bat`으로 실행할 거라면 이 단계는 안 해도 된다** — 더블클릭하면 실행될 때 자동으로 설치한다 (처음 한 번은 몇 분 걸릴 수 있음, 창을 닫지 말고 기다리면 됨)
   - Mac/Linux 터미널로 직접 실행할 거라면 이 폴더에서 한 번만:
     ```bash
     pip install -r requirements.txt
     ```
   `ultralytics`가 딥러닝 라이브러리(torch)를 함께 설치해서 **처음 한 번은 다운로드에
   시간이 좀 걸린다** (수백 MB). 인터넷이 느리면 몇 분 정도 기다리세요.

## 폴더 구조

```
futsal-highlight/
├── 실행하기.bat        # (Windows) 더블클릭으로 바로 실행
├── run.py               # (Mac/Linux/터미널) 두 모드를 고르는 진입점
├── input_videos/        # 여기에 분석할 영상 파일을 넣으세요
├── output/
│   ├── highlight/       # 하이라이트 모드 결과 클립
│   └── analyze/         # 경기 분석 모드 결과 (report.html 등)
├── highlight/            # 하이라이트 모드 코드
├── analysis/             # 경기 분석 모드 코드
├── rating/                # 평점/MOM 계산 코드
└── requirements.txt
```

## 사용 방법

### Windows

1. `input_videos` 폴더에 영상 파일(.mp4/.mov/.avi/.mkv)을 넣습니다
2. **`실행하기.bat`을 더블클릭**합니다 (한글 파일명이 깨져서 안 보이면 대신 **`start.bat`**을 더블클릭하세요 — 내용은 완전히 같습니다)
3. 나오는 메뉴에서 `1`(하이라이트) 또는 `2`(경기 분석)를 입력하고 엔터
4. 끝나면 `output\highlight` 또는 `output\analyze` 폴더를 확인 (경기 분석은 `report.html`을 브라우저로 더블클릭해서 열어보세요)

### Mac / Linux (터미널)

```bash
cd futsal-highlight

# 하이라이트 모드
python run.py --mode highlight input_videos/경기영상.mp4 --output-dir output/highlight

# 경기 분석 모드
python run.py --mode analyze input_videos/경기영상.mp4 --output-dir output/analyze
```

## 1. 하이라이트 모드 (`highlight/`)

### 어떻게 동작하는가

딥러닝으로 "골"을 직접 인식하는 게 아니라, 골이 터졌을 때 실제로 관측되는
세 가지 신호를 결합해 잡아내는 방식이다.

1. **오디오 에너지 스파이크** (`audio_analysis.py`): 관중 함성/환호/휘슬로
   음량(RMS 에너지)이 로컬 평균 대비 급격히 튀는 구간을 탐지
2. **모션 스파이크** (`motion_analysis.py`): 옵티컬 플로우로 화면 전체의
   움직임 크기를 측정해, 세리머니 등으로 움직임이 급증하는 구간을 탐지
3. **공 속도 스파이크** (`object_detection.py`): 사전학습된 YOLOv8(COCO
   "sports ball" 클래스)로 공의 위치를 프레임마다 추적해, 공이 갑자기
   빨라지는 구간(강슛 후보)을 탐지 — 오디오/모션은 화면·소리 전체를 보는
   거친 신호라 슈팅처럼 작고 순식간에 일어나는 동작을 놓치는데, 공 자체를
   추적하면 이런 국소적 사건을 더 정확히 잡을 수 있다
4. **신호 결합** (`highlight_extractor.py`): 여러 신호가 비슷한 시간대에
   함께 튀면 "교차 검증됨"으로 보고 신뢰도를 크게 높이고(겹치는 신호가
   많을수록 더 크게), 대표 시각은 점수가 큰 신호 쪽으로 가중평균한다.
   한 신호만 잡히면 신뢰도를 낮춰서 후보로 남긴다
5. 신뢰도 순으로 정렬해 각 후보 시점 앞뒤로 `ffmpeg`를 이용해 클립을 잘라낸다

### 세부 옵션

`python run.py --mode highlight` 뒤에 붙일 수 있는 옵션들:

| 옵션 | 의미 |
|---|---|
| `--audio-z-threshold` / `--motion-z-threshold` / `--ball-z-threshold` | 값을 낮출수록 더 많은 후보를 잡지만 오탐도 늘어남 |
| `--use-ball-detection` / `--no-use-ball-detection` | YOLO 공 검출 신호 사용 여부 (기본 켜짐, 모델 로딩 시간이 있어 끌 수도 있음) |
| `--min-gap-sec` | 같은 장면이 여러 후보로 중복 검출되지 않게 하는 최소 간격 |
| `--corroboration-window-sec` | 서로 다른 신호를 "같은 사건"으로 볼 시간 오차 허용 범위 |
| `--min-confidence` | 이 값 미만인 후보는 버림 |
| `--max-clips` | 신뢰도 상위 N개까지만 추출 |
| `--pre-seconds` / `--post-seconds` | 후보 시점 앞/뒤로 몇 초씩 잘라낼지 |

### 한계 (반드시 읽을 것)

- **완벽한 정확도를 기대하면 안 된다.** 오탐(골이 아닌데 잡힘)과 누락(골인데 못 잡음)이 모두 발생할 수 있다
- 관중 함성이 약하거나(관중이 적은 조기축구 등), 촬영 위치가 멀어 모션 변화가 잘 안 보이면 오디오/모션 신호의 정확도가 떨어진다
- **공 검출도 완벽하지 않다.** 실제 테스트에서 슈팅이 가장 빠른 순간(모션 블러가 심한 프레임)에는 오히려 YOLO가 공을 놓치는 경우가 있었다. 대신 슈팅 직전 드리블처럼 공이 빨라지기 시작하는 지점은 잘 잡혔고, 클립을 넉넉히 잘라내면(`--post-seconds`를 크게) 그 뒤에 이어지는 실제 골/슈팅 장면도 클립 안에 포함된다
- 실제 영상마다 배경 소음/카메라 흔들림/공 크기와 색이 다르므로, 처음 몇 개 영상으로 `--*-z-threshold`, `--min-gap-sec` 값을 튜닝해가며 쓰는 것을 권장한다
- 창의적인 개인기·킬패스·반칙 판정처럼 정성적 판단이 필요한 장면은 이 방식으로 감지하지 않는다

### 실제 테스트 사례

18.9초짜리 실제 1v1 개인기+슈팅 클립으로 검증한 결과:
- 오디오+모션만 썼을 때는 실제 슈팅 장면(18.5초)과 무관한 지점을 1위로 잘못 뽑았다
- YOLO 공 검출을 추가하자, 실제 슈팅 직전 드리블 구간(15.7초 근방)에서 공 속도 스파이크가 잡혔고, 오디오/모션과 교차 검증되며 신뢰도 1위 후보가 됐다
- `--post-seconds`를 넉넉히 주니(7초) 추출된 클립이 실제 골키퍼 세이브 장면(18.5초)까지 포함했다

즉 이 휴리스틱 조합은 "완벽하게 정확한 시점"보다는 "진짜 장면이 포함된 넉넉한 클립"을 뽑는 데 강점이 있다.

## 2. 경기 분석 모드 (`analysis/`)

### 어떻게 동작하는가

풀경기/편집된 경기 영상에서 YOLOv8로 **공과 사람(선수) 위치를 프레임마다 검출**해
(`tracking.py`), 다음 두 종류의 후보 이벤트를 규칙 기반으로 뽑는다 (`events.py`):

1. **터치/패스 후보**: 공에 가장 가까운 사람의 위치가 화면 대각선 대비 일정
   비율 이상 갑자기 바뀌는 시점 (패스되거나 볼을 빼앗겼을 가능성)
2. **슈팅/강킥 후보**: 공의 속도가 로컬 평균 대비 급증하는 시점 (하이라이트
   모드의 공 속도 스파이크 로직을 그대로 재사용)

각 이벤트 시점의 썸네일 프레임과 함께 **HTML 리포트**로 정리한다 (`report.py`).
골대의 화면 좌표를 알려주면(`--goal-post-a`/`--goal-post-b`), 거리·각도 기반의
**참고용 득점확률(xG) 근사치**도 함께 표시한다.

### 세부 옵션

| 옵션 | 의미 |
|---|---|
| `--sample-fps` | 초당 몇 프레임을 분석할지 (낮추면 빠르지만 짧은 장면을 놓칠 수 있음) |
| `--touch-jump-ratio` | 터치/패스 후보로 볼 최소 위치 변화 비율 |
| `--shot-z-threshold` | 슈팅 후보로 볼 공 속도 급증 임계값 |
| `--min-gap-sec` | 같은 이벤트가 중복 검출되지 않게 하는 최소 간격 |
| `--goal-post-a "x,y"` / `--goal-post-b "x,y"` | 골대 양쪽 기둥의 화면 픽셀 좌표 (지정하면 참고용 xG 계산) |

골대 좌표는 영상 아무 프레임이나 이미지 뷰어로 열어서, 골대 기둥이 화면에서
몇 픽셀 지점인지 눈대중으로 읽으면 된다 (예: 왼쪽 기둥이 대략 (165, 650)).

### 왜 정밀한 xG가 아니라 "참고용 근사치"인가

프로 구단이 쓰는 정밀한 xG는 **다중 카메라로 보정된 좌표계**와 **대량의 실제
슈팅 데이터로 학습한 모델**이 필요하다. 폰 한 대로, 그것도 카메라가 움직이는
영상으로는 애초에 이 수준의 정확도가 불가능하다. 그래서 이 도구는:

- "골대에 가깝고 각도가 넓을수록 득점 확률이 높다"는 **일반적인 경향만** 반영한 단순 로지스틱 근사치를 낸다 — 실제 확률이 아니라 **상대적 참고 지표**로만 써야 한다
- **카메라가 고정되어 있고 골대 위치를 사람이 지정해준 경우에만** 계산한다. 골대 좌표를 안 주면 리포트에 그냥 "골대 위치가 지정되지 않아 생략" 이라고 나온다 — 틀린 숫자를 지어내는 것보다 안 보여주는 쪽을 택했다
- 카메라가 계속 움직이는 영상(패닝, 줌)에는 적용할 수 없다 — 골대 좌표가 프레임마다 달라지기 때문

### 이 모드가 하지 않는 것

- **"이 패스가 좋았다/나빴다" 같은 가치 판단은 하지 않는다.** 터치·슈팅 후보는
  "공/사람 위치가 이렇게 바뀌었다"는 기하학적 사실만 보여주고, 그게 좋은
  선택이었는지는 리포트를 보는 사람이 직접 판단해야 한다
- **선수 개인 식별은 하지 않는다.** "1번 선수가 어시스트했다"처럼 누가 누구인지
  추적하지 않는다 — 원거리 아마추어 영상에서 얼굴/신체로 개인을 식별하는 것은
  현재 기술로 안정적이지 않다 (하이라이트 모드에서도 같은 이유로 보류한 부분)

### 실제 테스트 사례

앞서 검증한 18.9초 클립을 그대로 경기 분석 모드로 돌려보니, 터치 후보 3개와
슈팅 후보 2개가 나왔고, 슈팅 후보 중 하나가 15.8초 근방으로 하이라이트 모드에서
찾은 실제 슈팅 직전 구간(15.7초)과 일치했다. 골대 좌표를 눈대중으로 지정해보니
두 슈팅 후보 모두 근접 거리 슈팅이라 참고용 득점확률이 90%대로 나왔는데,
실제로도 골대 바로 앞 1v1 마무리 장면이라 방향성 자체는 합리적이었다.

## 3. 평점 + MOM 계산 (`rating/`)

### 어떻게 동작하는가

- 모든 선수는 기본 평점 **6.0**에서 시작
- `rating/rating_engine.py`의 `WEIGHTS_FIELD` / `WEIGHTS_GOALKEEPER` 딕셔너리에 정의된
  가중치를 스탯에 곱해 더하고 뺀다. **가중치 크기는 "경기 결과에 미치는 실제 영향도"를
  기준으로 정했다** — 골/자책골/레드카드처럼 승패에 직결되는 사건은 크게, 패스 성공률처럼
  누적성 지표는 작게 반영한다 (정확한 값은 `rating_engine.py`의 주석·딕셔너리 참고)
- 패스 성공률은 시도 횟수가 너무 적으면(3회 미만) 보너스/페널티를 주지 않고,
  시도 횟수가 많을수록(`sqrt(시도수)`로 스케일) 영향력을 키운다
- 골키퍼는 선방(`saves`) 가중치가 추가되고, 공격 관여 지표는 절반 가중치로 줄어든 별도 표를 쓴다
- 최종 평점은 0.0~10.0 사이로 clamp
- `rating/mom_selector.py`는 경기 참여 선수들의 평점을 계산해 최고점 선수를 MOM으로
  선정한다. 동점이면 ①공격포인트(골+어시스트) 많은 순 → ②이름 오름차순으로 정한다

### 사용 예시

```python
from rating.models import MatchStat, Position
from rating.rating_engine import compute_rating
from rating.mom_selector import select_mom

striker = MatchStat(
    player_id="10", player_name="홍길동", team_id="A",
    position=Position.FIELD, minutes_played=40,
    goals=1, assists=1, shots_on_target=2,
)
print(compute_rating(striker))       # 9.3
print(select_mom([striker, ...]))    # MomResult(player_name='홍길동', rating=9.3, ...)
```

### 한계

- 가중치는 축구 상식과 "결정적 사건일수록 크게 반영"이라는 원칙으로 정한 초기값이지,
  실제 경기 데이터로 통계적으로 검증된 값이 아니다. 실제 서비스에 쓰려면 다수의
  실제 경기 데이터로 가중치를 보정(피드백 루프)하는 과정이 필요하다
- xG(기대득점) 같은 "상황별 가치" 모델은 포함하지 않았다 (예: 같은 유효슛이라도
  빈 골대 앞 슛과 각도 없는 슛은 가치가 다르지만, 지금은 동일하게 취급)

## 한계와 다음 단계

아래 기능들은 이번 프로토타입에 **의도적으로 포함하지 않았다** — 현재 기술로
아마추어 폰 촬영 영상 한 대만으로 안정적으로 자동화하기 매우 어렵기 때문이다:

- 골/유효슛/반칙/세트피스/개인기의 **딥러닝 기반 자동 분류** (지금은 오디오+모션+공속도 휴리스틱으로 "골/슈팅 가능성이 높은 시점"만 후보로 제시)
- **얼굴·신체 인식으로 선수를 자동 식별**해 스탯을 자동 기록하는 기능 (원거리 저해상도 영상에서 정확도가 크게 떨어짐 — 실현하려면 등번호 인식부터 시도하는 것을 권장)
- **다중 카메라 보정 기반의 정밀한 xG 계산** (경기 분석 모드는 카메라가 고정된 경우에 한해 참고용 근사치만 제공)
- **"그 패스가 좋았다/나빴다" 같은 전술적 가치 판단** (지금은 무엇이 일어났는지만 보여주고 판단은 사람이 함)
- 유니폼 색상 기반 팀 자동 구분, 수동 스탯 입력 UI, 시즌 통계 누적, 실제 모바일 앱

이 항목들은 난이도가 낮은 순으로 후속 단계에서 다룰 수 있다.
